# HY-World 2.0 可视化工具选取建议

本文面向 `outputs/worldmirror_repro_archway_full/` 这类 WorldMirror 2.0 复现产物，说明各输出文件适合用什么软件、平台或开源代码进行可视化，并给出三维重建、3D Gaussian Splatting 和算法调试过程中的工具选型建议。

## 1. 产物类型先分清楚

WorldMirror 2.0 的输出并不是单一 3D 格式，而是包含 3DGS、点云、相机、深度和法线等多种数据。仓库文档中对主要保存项的定义如下：

- `gaussians.ply`: 3D Gaussian Splatting。
- `points.ply`: depth-derived colored point cloud。
- `camera_params.json`: camera extrinsics and intrinsics。
- `depth/depth_*.npy`: raw float32 depth values `[H, W]`。
- `depth/depth_*.png`: normalized depth visualization。
- `normal/normal_*.png`: RGB normal map visualization。

代码层面也能看到：

- `camera_params.json` 保存 `num_cameras`、`extrinsics`、`intrinsics`。
- `points.ply` 字段是 `x/y/z + red/green/blue`。
- `gaussians.ply` 字段包含 Gaussian center、opacity、scale、rotation、颜色相关字段等。

因此，普通 PLY viewer 只适合看 `points.ply`；如果用普通点云软件打开 `gaussians.ply`，通常只能看到 Gaussian 中心点，不能正确表达 splat 的尺度、旋转、不透明度和真实渲染效果。

## 2. 总体推荐表

| 产物 | 本质 | 首选工具 | 备选工具 |
| --- | --- | --- | --- |
| `gaussians.ply` | 3D Gaussian Splatting | SuperSplat | PlayCanvas、GaussianSplats3D、Nerfstudio/gsplat viewer、UnityGaussianSplatting |
| `points.ply` | 彩色点云 | CloudCompare | Open3D、MeshLab、Rerun、ParaView |
| `camera_params.json` | OpenCV convention 的 c2w 外参 + K 内参 | Rerun | Open3D 自写 frustum、COLMAP 格式导出、Blender/Unity 转换脚本 |
| `depth/depth_*.npy` | raw float32 Z-depth | Python + matplotlib/OpenCV | Open3D 反投影、Rerun、NumPy debug 脚本 |
| `normal/normal_*.png` | RGB 法线可视化图 | 图片查看器 / Rerun | Gradio、OpenCV、浏览器 |
| `rendered/*.mp4`，若使用 `--save_rendered` | 渲染视频 | 普通视频播放器 | Web demo、报告/演示材料 |
| `sparse/0/*`，若使用 `--save_colmap` | COLMAP sparse model | COLMAP GUI | pycolmap、Open3D 转换脚本 |

## 3. Rerun 是什么，适合做什么

Rerun 可以理解成“给计算机视觉、三维重建、机器人和多模态算法使用的时间同步可视化调试器”。它不是传统建模软件，也不是专门的 3DGS renderer。

Rerun 最擅长把算法中间量统一记录并联动展示：

- 图像：RGB、depth visualization、normal map、mask。
- 3D：point cloud、trajectory、camera frustum、坐标系。
- 相机：intrinsics、extrinsics、pinhole camera。
- 算法状态：scalar 曲线、文本日志、检测框、分割结果。
- 时间轴：多帧、多速率数据同步查看。

对 HY-World 这类任务，Rerun 的价值主要是“联合调试”，例如：

- 检查 `camera_params.json` 的相机方向是否正确。
- 将 `depth_*.npy` 反投影后与 `points.ply` 对齐。
- 同时看输入图、depth、normal、点云和相机 frustum。
- 判断坐标系是否反了、尺度是否漂了、深度是否和点云一致。

它不适合作为 `gaussians.ply` 的首选 viewer。真实 3DGS 效果应优先用 SuperSplat、PlayCanvas 或 GaussianSplats3D。

## 4. Rerun 的同类替代

| 场景 | 推荐工具 | 相比 Rerun 的特点 |
| --- | --- | --- |
| 快速检查点云 | CloudCompare | 更专业的点云 GUI，适合裁剪、测距、配准、离群点检查 |
| 点云/mesh 算法处理 | Open3D | 更适合脚本化处理、法线估计、下采样、ICP、重建 |
| ROS/机器人在线调试 | RViz / Foxglove | ROS topic、TF、传感器流接入更自然 |
| 自定义 Web 3D 调试界面 | Viser | 更适合自己写交互 UI、滑条、按钮、render callback |
| NeRF/3DGS 训练监控 | Nerfstudio viewer / gsplat viewer | 更贴近训练、novel view rendering 和 splat 渲染 |
| 3DGS 编辑与发布 | SuperSplat | 更适合直接查看、裁剪、清理、优化和发布 splat |
| Web 产品化 | PlayCanvas / GaussianSplats3D | 更适合前端嵌入、WebXR、轻量发布 |
| 大规模科学可视化 | ParaView | 适合大数据、多字段、科学计算和体数据 |
| DCC/影视流程 | Blender + 3DGS 插件 | 适合动画、镜头、材质/合成流程，但插件兼容性需验证 |

## 5. 3DGS 渲染工具怎么选

### 5.1 SuperSplat：查看和编辑 3DGS 的首选

适用对象：`gaussians.ply`。

推荐用途：

- 快速查看 HY-World 输出的 3DGS 效果。
- 裁剪、清理、调整、检查 splat 质量。
- 导出更适合 Web 发布的格式。
- 生成演示或在线分享。

使用方式：

1. 打开 `https://superspl.at/editor`。
2. 拖入 `outputs/worldmirror_repro_archway_full/gaussians.ply`。
3. 检查视角、边界、透明噪声、漂浮 splat、尺度和整体观感。

判断标准：

- 如果 SuperSplat 里效果自然，但普通 PLY viewer 里像散点，这是正常的。
- 如果 SuperSplat 里也有大量漂浮、破碎或尺度异常，应回到输入视角数量、mask、depth/normal 和相机估计上排查。

### 5.2 PlayCanvas：Web/产品发布

适用对象：经过清理或压缩的 3DGS。

推荐用途：

- 浏览器展示。
- 交互式 Web demo。
- WebXR / 游戏化展示。
- 产品级轻量分发。

前沿做法通常是：

```text
gaussians.ply -> SuperSplat 清理/裁剪 -> SOG 或 SPZ -> PlayCanvas / Web app
```

原始 PLY 是研究和交换格式；Web 发布时建议转成 SOG 或 SPZ 这类压缩格式，以降低加载体积和网络传输成本。

### 5.3 GaussianSplats3D：Three.js 生态

适用对象：想把 3DGS 嵌入自研前端或 Three.js 应用。

推荐用途：

- 自定义网页应用。
- 与其他 Three.js 几何、UI、交互逻辑结合。
- 快速做产品原型。

如果目标是 Web 工程集成，而不是单纯看效果，GaussianSplats3D 往往比桌面 viewer 更方便。

### 5.4 Unity / Unreal / Blender

适用对象：引擎或 DCC 流程。

建议：

- Unity：可尝试 UnityGaussianSplatting 等开源插件，适合实时交互原型。
- Unreal：插件生态变化较快，需重点验证 PLY 字段兼容性和运行时性能。
- Blender：适合离线镜头、动画、合成和资产检查，但不同 3DGS 插件对字段、SH、opacity、scale 的支持不完全一致。

重要提醒：

3DGS 本身不是 mesh，也没有天然碰撞体。做游戏、仿真或交互时，当前更稳的工程方案是：

```text
3DGS 负责视觉呈现 + proxy mesh / collider / navmesh 负责物理和交互
```

## 6. 点云与三维重建工具怎么选

### 6.1 CloudCompare：点云 GUI 首选

适用对象：`points.ply`。

推荐用途：

- 看点云整体形状和颜色。
- 查噪声、离群点、漂浮点。
- 裁剪局部区域。
- 测量尺度和距离。
- 多点云对齐、粗配准。

CloudCompare 比 Rerun 更适合“点云质量检查”和人工清理。

### 6.2 Open3D：脚本化几何处理首选

适用对象：`points.ply`、depth 反投影点云、mesh 生成、算法验证。

快速查看命令：

```bash
conda run -n hyworld2 python -c "import open3d as o3d; p=o3d.io.read_point_cloud('outputs/worldmirror_repro_archway_full/points.ply'); o3d.visualization.draw_geometries([p])"
```

推荐用途：

- 点云读取、显示、下采样。
- 法线估计。
- ICP / registration。
- depth + intrinsics + extrinsics 反投影。
- 点云转 mesh 的初步实验。

注意：

当前复现样例只有 2 张图。对于这种输入，强行 mesh 化通常不如直接看 `gaussians.ply` 或 `points.ply` 可靠。Mesh reconstruction 更适合多视角覆盖充分的结果。

### 6.3 MeshLab / ParaView

MeshLab 适合 mesh 清理、简化、重建实验，也能看点云；ParaView 适合更大规模、科学计算、多字段可视化。对当前 HY-World smoke test 来说，它们不是第一选择，但在后处理和批量分析中有价值。

## 7. 相机、深度、法线怎么可视化

### 7.1 `camera_params.json`

这个文件不应当被当作“展示资产”，它是调试坐标系、重投影和多视角一致性的核心。

推荐用途：

- 画 camera frustum。
- 检查相机轨迹和相对位姿。
- 将 depth 反投影到世界坐标。
- 与点云或 Gaussian centers 对齐检查。
- 导出 COLMAP / Nerfstudio / Blender / Unity 所需坐标。

注意坐标系：

WorldMirror 文档说明 `camera_poses` 是 camera-to-world，即 c2w，并使用 OpenCV convention。导入 Blender、Unity、OpenGL 或 Nerfstudio 时，需要显式处理坐标轴约定差异。

如果希望用 COLMAP GUI 查看，可以重新运行 pipeline 并加上：

```bash
--save_colmap
```

这样会输出 `sparse/0/cameras.bin`、`images.bin`、`points3D.bin`，更适合 COLMAP 工具链。

### 7.2 `depth/depth_*.npy`

这是 raw float32 depth。建议不要只看 normalized PNG，因为归一化图会隐藏真实尺度和异常值。

推荐检查：

- min / max / percentile。
- 直方图。
- colormap 可视化。
- 与相机内参 K 结合反投影到点云。
- 与 `points.ply` 对齐检查。

示例：

```bash
conda run -n hyworld2 python - <<'PY'
import numpy as np
import matplotlib.pyplot as plt

d = np.load("outputs/worldmirror_repro_archway_full/depth/depth_0000.npy")
lo, hi = np.nanpercentile(d, [2, 98])
plt.imshow(d, cmap="turbo", vmin=lo, vmax=hi)
plt.colorbar()
plt.title(f"depth_0000, p2={lo:.3f}, p98={hi:.3f}")
plt.show()
PY
```

### 7.3 `normal/normal_*.png`

这是 RGB 法线可视化图，适合快速检查表面方向是否连续、边界是否破碎、局部几何是否异常。

如果要做严谨法线误差评估，建议扩展 pipeline 保存 raw normal tensor，而不是只依赖 PNG。PNG 更适合人工观察和报告展示。

## 8. HY-World 自带 Gradio App

仓库自带 `hyworld2.worldrecon.gradio_app`，界面中包含：

- 3D Gaussian Splatting。
- Point Cloud / Mesh。
- Depth。
- Normal。
- Camera Parameters。

启动方式：

```bash
conda run -n hyworld2 bash -lc '
export LD_LIBRARY_PATH=$CONDA_PREFIX/lib:$CONDA_PREFIX/targets/x86_64-linux/lib:${LD_LIBRARY_PATH:-}
python -m hyworld2.worldrecon.gradio_app --port 8081
'
```

它适合后续交互式上传、重跑和查看。对于已经由 CLI 生成的目录，推荐直接使用 SuperSplat、CloudCompare/Open3D 和 Rerun 组合来检查。

## 9. 当前复现结果的推荐查看路线

当前已验证输出目录：

```text
outputs/worldmirror_repro_archway_full/
```

建议顺序：

1. 打开 `gaussians.ply`：
   - 用 SuperSplat 查看真实 3DGS 效果。
   - 关注整体观感、漂浮噪声、透明区域、边界和尺度。

2. 打开 `points.ply`：
   - 用 CloudCompare 或 Open3D 查看点云几何。
   - 关注点云是否散、是否有明显离群点、相机方向是否合理。

3. 检查 `depth/depth_*.npy`：
   - 用 Python 看 percentile colormap 和深度范围。
   - 必要时反投影到 3D，与 `points.ply` 对齐。

4. 检查 `normal/normal_*.png`：
   - 观察表面方向和边缘连续性。

5. 检查 `camera_params.json`：
   - 用 Rerun 或 Open3D 画 camera frustum。
   - 确认 c2w、K、点云、depth 之间一致。

6. 对外演示或发布：
   - 重新运行 pipeline 可加 `--save_rendered --render_depth` 生成视频。
   - 或将 `gaussians.ply` 清理后转成 SOG/SPZ，用 PlayCanvas 或 Three.js 发布。

## 10. 工具选择结论

如果只选一个工具，很容易看偏。建议按目的组合使用：

- 看 3DGS 是否好看：SuperSplat。
- 看点云几何是否靠谱：CloudCompare / Open3D。
- 查算法哪里错：Rerun。
- 做自定义交互调试 UI：Viser。
- 做网页产品和在线展示：PlayCanvas / GaussianSplats3D。
- 做 ROS/机器人在线调试：Foxglove / RViz。
- 做引擎落地：Unity/Unreal 的 3DGS 插件 + proxy mesh/collider/navmesh。

对当前 HY-World 2.0 复现产物，最实用的“三件套”是：

```text
SuperSplat 看 gaussians.ply
CloudCompare/Open3D 看 points.ply
Rerun 联合看 camera + depth + normal + points + input images
```

这套组合能覆盖视觉效果、几何质量和算法调试三个层面，也更接近当前三维重建和 3DGS 工程实践中的主流做法。
